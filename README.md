## Quick start

```bash
npm install
cp .env.example .env.local
npm run dev
```

المتغير الأساسي هو `VITE_API_BASE_URL` ويجب أن يكون أصل الباك إند فقط، مثل `https://ziadkamalaln2842-001-site1.etempurl.com`.

## Commands

```bash
npm run dev      # تشغيل محلي
npm run lint     # فحص الكود
npm run build    # بناء الإنتاج (يشمل توليد sitemap.xml)
npm run preview  # معاينة نسخة البناء محليًا
npm run format   # تنسيق الكود بـ Prettier
```

## نظرة عامة على المنصة

Academia منصة تعليمية عربية أولاً (RTL حقيقي، ثنائية اللغة عربي/إنجليزي) لطلاب المرحلة الثانوية (توجيهي)، بخمس مساحات أدوار منفصلة:

| الدور                  | الاحتياج الرئيسي                                       |
| ---------------------- | ------------------------------------------------------ |
| 👨‍🎓 الطالب              | مكتبة منظّمة، تتبّع إنجاز، بنك أخطاء، امتحانات تجريبية |
| 👩‍🏫 المعلم              | رفع محتوى، إدارة كورسات واختبارات، متابعة أداء الطلاب  |
| 👪 ولي الأمر           | تقرير أسبوعي مختصر عن ابنه، بدون تدخّل بخصوصيته        |
| 🧑‍💼 المشرف (Supervisor) | جودة تدريس، متابعة معلمين وطلاب، تقارير دورية          |
| 🛠️ الإدارة (Admin)     | مستخدمون، أدوار وصلاحيات، مراجعة محتوى، منهاج، مدفوعات |

**التموضع التنافسي:** عربي أولاً بالتصميم (مو ترجمة)، تصنيف منهجي صارم (فصل ← مادة ← وحدة ← درس)، وخصوصية الطالب (ولي الأمر يشوف ملخص بس). الميزة التنافسية طويلة المدى المستهدفة — بنك أخطاء مرتبط بمراجعة يومية فعلية — **لسا قيد البناء ومو مطلوب نسوّقها كأنها جاهزة** (راجع [قاعدة الحقيقة](#قاعدة-الحقيقة-truth-rule--مبدأ-غير-قابل-للتفاوض)).

## حالة الصفحات — جدول شامل لكل دور

**رمز الحالة:**

- 🟢 **جاهزة** — منطق كامل وبيانات صادقة (فاضية بصدق أو self-reported)، جاهزة تفاهيميًا لدمج API حقيقي بدون إعادة بناء الواجهة.
- 🟡 **جزئية** — الواجهة والمنطق موجودين، بس بيانات وهمية كانت فيها (اتصلّحت لصفر/فاضي)، أو التسمية أبسط من الاسم الطموح مؤقتًا.
- 🔴 **معاينة تصميم فقط** — بيانات ثابتة بالكود، بدون منطق فعلي (موسومة بشارة "معاينة تصميم" بالواجهة).
- 🔗 **باك اند مطلوب** — Yes = محتاج endpoint حقيقي ليشتغل بالكامل. حاليًا الباك اند (Academia) فيه فقط: Auth, User, UserPermission, Constant, Page, Home — **لا يوجد أي endpoint لكورسات/محتوى/امتحانات/مدفوعات/إشعارات بعد.**

## Current integration boundary

**محدَّث 14 سبتمبر 2026 — راجع [`docs/api/frontend-integration-status.md`](docs/api/frontend-integration-status.md) للجدول الكامل (32 endpoint، حالة كل وحدة).**

الباك اند (Academia) فيه فعليًا **8 controllers**: Auth, User (بما فيها
تعديل الملف الشخصي وتغيير كلمة المرور — رُبطا هالجلسة)، UserPermission,
Constant, Page, **Wallet** (محفظة/شحن/سحب — 10 endpoints، مربوطة
بالكامل)، **Parent** (مربوطة بالكود، **معطّلة عمليًا** بسبب فجوة باك
اند: لا endpoint لربط الأبناء، و"الطالب" كيان منفصل عن `User` بدون أي
كود ينشئه)، وHome (redirect فقط). الكورسات والدروس والتسجيلات
والحضور/الامتحانات الحقيقية والإشعارات لسا تنتظر عقود API — موثّقة
كخطة مستقبلية بـ`docs/product/` (راجع تقرير SRS/System Design المرفق
من الفريق).

لا تعتبر UI guards أو localStorage حماية للخادم. البيانات المتبقية
بصفحات المحتوى/المنهج/الحضور (عدا Auth/Users/Permissions/Wallet) لسا
`in-memory` بالفرونت (`src/lib/*-data.ts`) بانتظار الباك اند.

## نظام التصميم (Design System)

**المصدر الحقيقي الوحيد:** `src/styles.css` — Design tokens مركزية عبر CSS variables، دعم كامل Dark/Light + RTL/LTR ديناميكي (`dir` يتحدّث فعليًا عند تبديل اللغة، مش ثابت).

| الطبقة                       | التفاصيل                                                                                                                                                                        |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **الخطوط**                   | Reem Kufi (عناوين `h1/h2/h3` تلقائيًا) + Cairo (متن) + IBM Plex Mono — تمايز حقيقي، مطبّق بطبقة `@base` عامة                                                                    |
| **الألوان**                  | Semantic tokens (`--color-primary`, `--color-success`, `--color-destructive`...) عبر Light/Dark، مافي hex مكتوب يدويًا بالمكوّنات                                               |
| **الظلال (Elevation)**       | 3 مستويات فعلية (`shadow-elevation-1/2/3`) بمنحنيات `color-mix(in oklab...)` تتكيّف تلقائيًا مع الثيم                                                                           |
| **نصف القطر**                | مقياس متدرّج من متغيّر واحد (`--radius`) عبر 7 أحجام                                                                                                                            |
| **التمييز النصي**            | `text-gradient` (اتجاه يتبع `dir` تلقائيًا، ليس ثابتًا) + `text-highlight` (تسطير "قلم تحديد") — استخدام انتقائي، مش كل عنوان                                                   |
| **الحركة**                   | `hover-lift`/`hover-press`/`btn-shine`/`glow-primary`/`panel-swap` — منحنيات `cubic-bezier` احترافية، `prefers-reduced-motion` مُحترم بقاعدة عامة شاملة + استثناءات مستهدفة     |
| **الرسومات (Illustrations)** | SVG مخصصة (`src/components/site/illustrations.tsx`) بألوان CSS variables — تُستخدم للمفاهيم المحورية بالصفحات العامة فقط، مو كل عنصر (الصفحات الداخلية تبقى بسيطة/وظيفية عمدًا) |
| **الصور**                    | نمط `PhotoAvatar` مشترك (`src/components/site/photo-avatar.tsx`): صورة حقيقية + fallback تلقائي لأيقونة، بمسار ثابت متوقّع (`public/team/...`, `public/courses/covers/...`)     |

**مبدأ حرج:** `hover-lift` (ارتفاع + ظل) لازم يُستخدم **فقط** على عناصر قابلة فعليًا للنقر (Link/Button حقيقي). استخدامه على محتوى ثابت = كذبة بصرية (Affordance كاذب). رُصد وصُحِّح 7 مواضع بهالجلسة، بينها مكان واحد مشترك (`kit.tsx StatGrid`) أثّر تصحيحه على الـ42 صفحة دفعة وحدة.

## المعمارية والبنية (Architecture & Structure)

```
Routes (src/routes) ──> Components (app/site/ui) ──> Hooks ──> Integrations ──> Backend (Academia API)
                                                          └──> lib/*.functions.ts (server functions مؤقتة، in-memory)
```

| الطبقة           | المسار                                 | المسؤولية                                                                                               |
| ---------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Routes           | `src/routes/**`                        | تركيب الشاشة، SEO meta، RBAC guard عبر `<Guard pageKey="...">`                                          |
| UI primitives    | `src/components/ui`                    | مكوّنات عامة بلا معرفة بـbusiness domain (Button, Dialog, Input...)                                     |
| App components   | `src/components/app`                   | مكوّنات مشتركة للوحات (`kit.tsx`: AppPage, StatGrid, Panel, RowList, DataTable, EmptyState, QuickLinks) |
| Site components  | `src/components/site`                  | الـshell العام، الهيدر/الفوتر، illustrations، مكوّنات التسويق                                           |
| Admin components | `src/components/admin`                 | مدراء شاشات الأدمن (users-manager, roles-manager...)                                                    |
| Hooks            | `src/hooks`                            | `use-session`, `use-access` (RBAC check عبر `can()`), `use-scroll-reveal`                               |
| Integrations     | `src/integrations/backend`             | Auth client الحقيقي المتصل بـ Academia API                                                              |
| lib (مؤقت)       | `src/lib/*.functions.ts` + `*-data.ts` | Server functions تحاكي API حقيقي فوق مصفوفات in-memory، بانتظار الباك اند                               |
| i18n             | `src/i18n/locales/*.json`              | `ar.json`/`en.json` (صفحات مشتركة+معقّدة) و`ar.pages.json`/`en.pages.json` (صفحات عامة بسيطة)           |

**نمط `*-data.ts` القياسي:**

```ts
// كل جدول بيانات مؤقت يوثّق بتعليق: هل فاضٍ بقصد (بيانات نشاط أشخاص
// حقيقيين غير موجودة)، ولا فيه بيانات نموذجية شرعية (بيانات المستخدم عن
// نفسه، أو محتوى كتالوج عام قابل للتعديل).
export const SOME_TABLE: SomeRow[] = [/* ... */];
```

**نمط Server Function القياسي:**

```ts
export const saveSomething = createServerFn({ method: "POST" })
  .middleware([requireAuth])
  .inputValidator((input) => zodSchema.parse(input))
  .handler(async ({ data, context }) => {
    await requirePermission(context.userId, "page_key", "action");
    // منطق CRUD على المصفوفة in-memory
  });
```

**RBAC:** `src/lib/rbac-static-data.ts` يعرّف شجرة صفحات/صلاحيات ثابتة (اسم عربي + إنجليزي + مسار + أيقونة لكل صفحة)، تُستهلك عبر `useAccess()` (`can(pageKey, action)`) و`<Guard pageKey>` لحجب العرض على مستوى الواجهة (**مو حماية خادم حقيقية** — راجع `docs/security/frontend-route-protection.md`).

## قاعدة الحقيقة (Truth Rule) — مبدأ غير قابل للتفاوض

المبدأ الأهم يلي حكم كل تعديل بهالمشروع، وموثّق أصلاً بـ[`docs/decisions/0001-frontend-backend-boundary.md`](docs/decisions/0001-frontend-backend-boundary.md):

> **الواجهة ما بتعرض بيانات تجريبية على أنها إنجازات أو نتائج إنتاجية حقيقية.**

### التمييز العملي (استُخرج من مراجعة شاملة لكل الصفحات):

| النوع                                                                 | القرار                                                                                    | مثال                                                                                       |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| بيانات المستخدم **عن نفسه** (self-reported)                           | ✅ يبقى، طالما شفاف وقابل للتعديل                                                         | نقاط الطالب، أيامه المتتالية، كورساته المشترك فيها                                         |
| بيانات نشاط **أشخاص آخرين حقيقيين** (طلاب/معلمين/معاملات/تقييمات)     | ❌ صفر/فاضٍ حتى تتوفر بيانات حقيقية                                                       | "96 طالب مشترك"، "68% من طلابك أخطأوا"، معاملة مالية بمبلغ ثابت                            |
| محتوى كتالوج عام هيكلي (أمثلة كورسات/معلمين معروضة للزوار)            | ✅ يبقى كبيانات نموذجية معلنة                                                             | كتالوج `public-catalog-data.ts` — أسماء وأسعار مثال، بس بمخطط production-ready             |
| صفحة/عنصر تحكم **يصف آلية غير موجودة** (مؤقّت، تصحيح آلي، إشعار فعلي) | ❌ صياغة تُصحَّح لتطابق الواقع، أو تُوسم "معاينة تصميم"                                   | "محاكي الامتحان" ← "امتحاناتي التجريبية"، مفتاح "تذكير" ← "علّمها كمهمة (بدون إشعار فعلي)" |
| صياغة تسويقية **بصفحة عامة** عن رؤية المنتج النهائية                  | ✅ يجوز صياغتها بثقة (Build forward)، **إلا** أرقام مالية/عمولة محددة قبل اعتمادها رسميًا | "للمعلمين" تصف الرؤية الكاملة، بس دخل المعلم = "قادم" مو رقم ثابت                          |

**فحص سريع قبل أي إضافة نص/بيانات جديدة:** _"لو محتوى تاني غير هذا، هل كان بنفس القرار؟"_ — لو الجواب دايمًا "أيوا نفس القرار بغض النظر عن المحتوى"، فهذا قالب جاهز غير مدروس، لازم مراجعة.

## ممارسات هندسة البرمجيات بالمشروع

- **DRY عبر مكوّنات مشتركة:** أي إصلاح بمكوّن مشترك (`kit.tsx`, `photo-avatar.tsx`, `illustrations.tsx`) ينعكس على كل الصفحات المستخدمة له دفعة وحدة — يُفضَّل دايمًا عن تكرار الإصلاح صفحة-صفحة.
- **التحقق قبل الافتراض:** أي ادّعاء عن "شو موجود بالكود" يتحقّق منه بقراءة فعلية (`grep`/`view`)، مش بالتخمين من اسم الصفحة أو النص الظاهر.
- **مراجعة ثانية إلزامية لأي كود تفاعلي:** بعد كتابة أي منطق تفاعلي (state, animation, mutation)، تُقرأ الكود مرة ثانية بعين نقدية — توازن الأقواس مش كافي للتأكد من صحة السلوك، خصوصًا الأنيميشن (CSS transforms قابلة للتراكم بشكل غير متوقّع).
- **Diff-based patches:** كل تغيير يُسلَّم كـ`git diff` تراكمي (`git apply` بالتسلسل)، مو كتابة الملف كامل من جديد — أسهل مراجعة وأقل خطر تعارض.
- **i18n متزامن دايمًا:** أي تعديل نص بالعربي يترافق بنفس التعديل بالإنجليزي بنفس الجلسة، مش لاحقًا.
- **لا صفحة كاملة تعتمد على mock data بدون وسم preview** (راجع `docs/architecture/routes.md`).
- **RBAC على مستوى الواجهة فقط حاليًا:** `<Guard>` و`can()` يحجبون العرض، ومش بديل عن تفويض خادم حقيقي — أي endpoint حقيقي لازم يتحقق من الصلاحية بنفسه بغض النظر عن الواجهة.

## أساسيات Prompt Engineering لهذا المشروع

لو طلبت من مساعد AI (Claude أو غيره) شغل على هالمشروع، هاي المعلومات بتوفر وقت ومراجعات:

### سياق لازم تعطيه دايمًا

1. **حالة الباك اند الفعلية:** 7 controllers بس (Auth, User, UserPermission, Constant, Page, Home) — أي طلب "اربط هالصفحة بالباك اند" مستحيل تقنيًا لحد الآن.
2. **قاعدة الحقيقة** (فوق) — أي نص/بيانات جديدة لازم تُفحص عليها.
3. **الاسم الحالي لأي فيتشر قد يكون متعمّد التواضع** (زي "امتحاناتي التجريبية" بدل "محاكي الامتحان") — لا تُرجعه للاسم الطموح بدون تأكيد إنه بُني فعليًا.
4. **نظام التصميم بـ`src/styles.css`** — أي CSS جديد لازم يستخدم الـtokens الموجودة (`var(--color-*)`)، مو قيم hex مباشرة.

### طريقة طلب تغيير UI/UX بفعالية

- بدل "حسّن التصميم" (عام جدًا) → حدّد: أي صفحة، أي محور (محتوى/بنية/بصري/حركة)، ومقارنة بشو (معيار Notion؟ Linear؟ الصفحات العامة بالمشروع نفسه؟).
- اطلب تفريق واضح: هل هاد المكوّن قابل للنقر فعليًا؟ (يحدد استخدام `hover-lift` من عدمه).
- لأي "فيتشر مستقبلي"، اسأل صراحة: **مبني فعليًا، ولا لسا وصف/تصميم بس؟** — هذا يحدد صياغة النص (مضارع مؤكد VS "قادم").

### طلب مراجعة/تدقيق فعّال

- اطلب فحص **الكود الفعلي** (data model + server function)، مو بس النص الظاهر بالواجهة — أغلب الاكتشافات المهمة بهالمشروع طلعت من مقارنة الوصف بالكود ورا الكواليس.
- اسأل: "لو كان محتوى/سياق مختلف، هل كان القرار نفسه؟" — يكشف القوالب الجاهزة غير المدروسة.

### تسليم النتائج

- اطلب `git diff` تراكمي بدل ملفات كاملة لمراجعة أسهل وأسرع.
- اطلب تحقّق تطبيق الباتش (`patch --dry-run`) قبل التسليم، مو بس "شكله صح".

## سجل القرارات المعمارية (ADRs)

| #    | القرار                                             | الملف                                                                                                                |
| ---- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 0001 | حدود الفرونت/الباك اند — لا اختراع endpoints وهمية | [`docs/decisions/0001-frontend-backend-boundary.md`](docs/decisions/0001-frontend-backend-boundary.md)               |

**قرارات هالجلسة (غير موثّقة كـADR رسمي بعد، مقترح تُضاف):**

- تسمية متواضعة مؤقتة للفيتشرز غير المبنية فعليًا (محاكي الامتحان، المجتمع) بدل حذفها أو تركها بأسماء طموحة.
