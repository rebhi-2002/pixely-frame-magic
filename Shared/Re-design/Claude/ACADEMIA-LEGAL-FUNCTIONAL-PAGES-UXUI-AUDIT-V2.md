# ACADEMIA — المساعدة، تواصل معنا، الخصوصية، الشروط، إلغاء الاشتراك — UX/UI AUDIT (V2)

> تحقّق مباشر من الملفات الخمسة. هاي أسرع مجموعة مراجعة لحد الآن — أغلبها
> صفحات وظيفية بسيطة أصلاً، بس طلع فيها **اكتشاف وظيفي مهم (مش بصري) لازم
> يُعالَج قبل أي إطلاق فعلي**.

---

## 0. التحقق المباشر — اكتشاف مهم: نموذجين غير موصولين فعلياً بأي باك اند

| الصفحة                                | المصدر                                     | النتيجة                                                                                                                                                                                                                                                                   |
| ------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/contact` — نموذج التواصل            | `contact.tsx` سطر 44-51، تعليق بالكود نفسه | ⚠️ **مهم**: `window.setTimeout(..., 600)` يحاكي نجاح الإرسال، مع تعليق صريح بالكود: _"نموذج واجهة كامل وجاهز للإنتاج. الربط الفعلي بالبريد/التخزين يُنفَّذ عند توصيل الـbackend"_ — يعني **أي رسالة يبعتها زائر فعلياً حالياً ما بتوصل لحد**، بس بتظهر "تم الإرسال بنجاح" |
| `/unsubscribe` — نموذج إلغاء الاشتراك | `unsubscribe.tsx` سطر 30-34                | ⚠️ **نفس المشكلة بالضبط**: `toast.success` فوري بدون أي استدعاء API فعلي                                                                                                                                                                                                  |
| `/privacy`, `/terms`                  | ملفين 31 سطر لكل وحدة                      | ✅ نص قانوني مُقسَّم بأقسام (عنوان+وصف)، بدون أي مشكلة — تصميم نظيف ومناسب أصلاً                                                                                                                                                                                          |
| `/help`                               | `help.tsx` (100 سطر)                       | ✅ مركز مساعدة حقيقي: بحث فوري + أكورديون FAQ بعنصر `<details>` الأصلي (وصول سليم بدون جافاسكربت إضافي)                                                                                                                                                                   |

**هاد أهم اكتشاف بهالمجموعة، وأهم من أي ملاحظة بصرية**: نموذجين (تواصل معنا،
إلغاء الاشتراك) حالياً **واجهة فقط بدون وظيفة فعلية** — لو الموقع نُشر
هيك، أي طالب أو معلّم أو ولي أمر بيبعت رسالة أو يحاول يلغي اشتراكه بإيميل
**رح ياخد رسالة "نجح!" كاذبة بينما شي ما صار فعلياً**. هاي بالضبط نفس فئة
مشكلة "الصدق مع الزائر" اللي بنينا عليها كل قرار سابق — بس هون المشكلة
وظيفية حقيقية مش بصرية، وأولويتها **أعلى من أي تعديل تصميم بهالوثيقة كلها**.
لازم تتحل (ربط فعلي بباك اند/بريد) قبل أي إطلاق، بغض النظر عن أي قرار تصميمي.

---

## 1. الفئة المستهدفة لهاي الصفحات

زائر بحاجة عملية محددة جداً (سؤال دعم، شكوى، رغبة بإلغاء اشتراك، أو حاجة
قانونية) — **مو بمزاج "استكشاف واقتناع"**. الأثر المباشر: **الوضوح والسرعة
أهم من أي هوية بصرية غنية** — هاي أضعف صفحات بالموقع من ناحية "احتياج تصميم
مميّز"، وأقواها من ناحية "لازم تشتغل صح تقنياً 100%".

## 2. القرارات

### 2.1 السياسة البصرية — تعديلات بسيطة فقط

| الصفحة               | العنصر                                                              | القرار                                                                                                                                                           |
| -------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/help`              | أيقونة `LifeBuoy` بدائرة أعلى الهيرو                                | **REMOVE** — نفس نمط كل أيقونة هيرو زخرفية سابقة                                                                                                                 |
| `/help`              | خلفية `surface-mesh` بالهيرو                                        | **تُخفَّف** حسب هرمية الخلفيات الجديدة (وثيقة الأسس، قسم 6) — صفحة ثانوية نصية، توهّج خفيف بلون واحد كحد أقصى، بدون الشبكة الملوّنة الكاملة                      |
| `/contact`           | أيقونة `MessageSquareText` بدائرة أعلى الهيرو                       | **REMOVE**                                                                                                                                                       |
| `/contact`           | 3 أيقونات (`Mail`/`Clock`/`Headset`) بمربعات ملوّنة بالشريط الجانبي | **REMOVE** — تمايز بالتايبوغرافيا فقط (عنوان بولد + نص تحته)، بدون رمز. البريد الإلكتروني نفسه (`support@academia.app`) أوضح "أيقونة" من أي رمز بصري             |
| `/contact`           | نفس خلفية الهيرو                                                    | تُخفَّف، نفس منطق `/help`                                                                                                                                        |
| `/unsubscribe`       | أيقونة `MailX` بدائرة                                               | **REMOVE**                                                                                                                                                       |
| `/privacy`, `/terms` | —                                                                   | **بدون تغيير** — الصفحتين أصلاً بدون هيرو مزخرف أو أيقونات، `narrow` container (max-w-3xl) مطابق تماماً لتوصية عرض المحتوى بوثيقة الأسس. **KEEP كما هما بالضبط** |

### 2.2 الأولوية الوظيفية (تُنفَّذ بشكل مستقل عن أي قرار تصميمي)

1. ربط `/contact` بخدمة بريد فعلية (Resend أو ما شابه) أو تخزين فعلي
   بقاعدة بيانات — إزالة الـ`setTimeout` المؤقت.
2. ربط `/unsubscribe` بمنطق فعلي يلغي التفضيلات المحددة من قاعدة بيانات
   حقيقية.
3. **لحد ما يصير الربط جاهز**: لو الموقع لازم يُنشر بمرحلة مؤقتة قبل جاهزية
   الباك اند، الأصدق هون هو رسالة توضّح صراحة "هاي الميزة قيد التجهيز، تواصل
   معنا مباشرة عبر البريد بالأسفل" بدل رسالة "تم الإرسال بنجاح" غير حقيقية —
   نفس مبدأ الصدق المطبّق بكل صفحة سابقة (زي "قيد الإعداد" بصفحة المعلّم).

## 3. ملف الأصول

لا يوجد أصول جديدة مطلوبة — كل التعديلات هون كودية (حذف أيقونات، تخفيف
خلفية) أو وظيفية (ربط باك اند)، بدون أي صورة جديدة.

---

## 4. الخطوة التالية

بهيك خلّصنا **كل** الصفحات التسويقية العامة والوظيفية بالفوتر. المتبقي
الوحيد من خطتك: **صفحات تسجيل الدخول/إنشاء حساب لكل دور** — هاي فئة مختلفة
كلياً بالغرض (إنجاز مهمة بأقل احتكاك، مش إقناع) ومنطقها مختلف لكل دور
(طالب/معلّم/ولي أمر)، فتستاهل وثيقتها الخاصة بمنهجية مُكيَّفة شوي عن باقي
الصفحات.
