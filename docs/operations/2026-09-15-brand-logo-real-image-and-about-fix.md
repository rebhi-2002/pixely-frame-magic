## 1) الشعار — من رسمة يدوية إلى الصورة الأصلية الحقيقية

الجلسة السابقة (`brand-logo-refresh.md`) بنت الشعار **يدوياً** (أشكال هندسية
مرسومة بالعين) اعتماداً على لوحة هوية بصرية (branding sheet) أرسلها المستخدم.
هالجلسة استبدلت هالرسمة كلياً: المستخدم بعت **الصورة الأصلية الحقيقية**
للشعار (PNG عالي الدقة 1254×1254، بدون خلفية بيضاء — شفافية حقيقية بقناة
alpha)، وطلب استخدامها **هي نفسها بالضبط** بدل أي إعادة رسم، مع التأكيد على
عدم التبكسل.

### ليش الرسمة اليدوية السابقة ما كانت كافية

كانت تقريب بصري جيد بس مش مطابقة 100% للتفاصيل الدقيقة (شكل القبعة، زاوية
الشريط تحتها، تفاصيل العلامة الداخلية بجسم الـA). الصورة الأصلية فيها تفاصيل
تصميمية (تدرّج لوني دقيق، طبقات الشريط تحت القبعة) صعب تكرارها يدوياً
بدقة 100%.

### الحل التقني (بدون تبكسل)

1. **استخراج الشعار الحقيقي**: قص الصورة الأصلية بالاعتماد على قناة الشفافية
   (alpha channel) الحقيقية — تأكدت بصرياً (بتركيبها فوق خلفية داكنة) إنه ما
   في أي هالة بيضاء أو حواف قذرة حوالين الشعار. النتيجة: مقطع نظيف 581×542px
   بشفافية حقيقية 100%، محفوظ كمرجع أساسي (master).
2. **قاعدة ذهبية لتفادي التبكسل**: كل الأحجام المُصدَّرة اتصغّرت (downscale)
   من هالمرجع، ولا وحدة منها كُبِّرت (upscale) — التصغير عملية آمنة بصرياً
   دائماً، التكبير هو يلي بيسبب تبكسل/تشويش.
3. **ضغط بدون فقدان جودة ظاهر**: استخدمت `pngquant` + `optipng` (أدوات ضغط
   PNG قياسية) لتصغير حجم الملفات — تحققت بصرياً بعد الضغط إنه ما في أي تقطّع
   (banding) بالتدرّج اللوني قبل ما اعتمدت النتيجة.

### الملفات النهائية المولَّدة من الصورة الأصلية (مش رسمة يدوية)

| الملف                                       | المصدر/المقاس                                                | الاستخدام                                                                  |
| ------------------------------------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------- |
| `public/brand/logo-mark.png`                | 320×299px (~24KB بعد الضغط)                                  | أيقونة الهيدر/السايدبار/شاشة تسجيل الخروج — عبر `<img>` بمكوّن `BrandLogo` |
| `public/favicon.svg`                        | صورة PNG مضمّنة (base64) داخل SVG، خلفية داكنة بزوايا مدوّرة | فافيكون المتصفح (SVG)                                                      |
| `public/favicon.ico`                        | 4 أحجام حقيقية (16/32/48/64) من نفس المصدر                   | فافيكون المتصفح (ICO، للمتصفحات يلي ما بتدعم SVG favicon)                  |
| `public/icons/icon-192.png`, `icon-512.png` | هامش عادي حوالين الشعار، خلفية داكنة `#0A0F1C`               | أيقونات PWA                                                                |
| `public/icons/icon-maskable-512.png`        | هامش أمان أوسع (safe zone ~56% من المساحة)                   | أيقونة PWA قابلة للقصّ بأشكال مختلفة حسب نظام التشغيل                      |

### `brand-logo.tsx` — من SVG بـ`currentColor` إلى `<img>` بلون ثابت

```tsx
export function BrandLogo({ className = "size-9" }: { className?: string }) {
  return <img src="/brand/logo-mark.png" alt="" className={`${className} object-contain`} />;
}
```

**قرار مهم اتحسم بهالجلسة**: الشعار الآن **لون ثابت (تدرّج ذهبي دائم)**، مش
`currentColor` يتغيّر مع الثيم متل الشعار القديم (شخصية الماسكوت). السبب:
الذهبي واضح ومقروء على الخلفية الغامقة *و*الفاتحة الاثنين (بيّنته صورة
المستخدم المرجعية بنفسها بمثالي Dark Mode وLight Mode — نفس الشعار بالضبط
بالاثنين). العنصر يلي بيتغيّر لونه مع الثيم هو **النص** ("Academia" جنب
الشعار بـ`BrandLockup`) عبر `text-foreground`، مش الأيقونة نفسها.

> **ملاحظة للمستقبل**: لو حداً حبّ يرجع لشعار SVG بـ`currentColor` (متغيّر
> اللون حسب الثيم) لأي سبب، لازم رسمة SVG يدوية نظيفة من جديد — مش ممكن
> استخراجها من صورة PNG بلون ثابت.

### لماذا الفافيكون هلق فيه تفاصيل كاملة (مش نسخة مبسّطة زي الجلسة السابقة)

الجلسة السابقة بنت نسخة مبسّطة بدون شرابة القبعة خصيصاً للفافيكون (16-32px)
لأن الرسمة اليدوية كانت تفقد وضوحها بهالحجم. الصورة الحقيقية (بتدرّجها
وتنعيمها الطبيعي) بانت أوضح بكثير بنفس الحجم حتى بكامل تفاصيلها — جرّبتها
بصرياً (16/32/48/64px) وطلعت مقروءة، فما احتجت نسخة مبسّطة منفصلة هالمرة.

## 2) صفحة "من نحن" — تصحيح مسمّيات الفريق

### المشكلة

3 أشخاص، كل الثلاثة بمسمّى "مؤسس" — وشخصين منهم (أحمد وزياد) بنفس المسمّى
**بالحرف الواحد** ("مؤسس — الباك اند") رغم إنه شغلهم مختلف فعلياً حسب
الوصف المرافق (أحمد: بنية تقنية وقواعد بيانات، زياد: أمان وبنية تحتية).

### هل 3 مؤسسين لمشروع واحد شي منطقي؟

**نعم** — شي شائع جداً بالمشاريع الناشئة (كل مؤسس مسؤول عن جزء مختلف). المشكلة
مش بعدد المؤسسين، كانت بتكرار المسمّى الحرفي لشخصين، يلي بيبين كـ"نسخ ولصق"
غير مقصود بدل تمايز حقيقي.

### الحل المطبّق (بالعربي والإنجليزي)

| الاسم         | المسمّى القديم                  | المسمّى الجديد                                      |
| ------------- | ------------------------------- | --------------------------------------------------- |
| ربحي إبراهيم  | مؤسس — الواجهة الأمامية والمنتج | **مؤسس مشارك** — الواجهة الأمامية والمنتج           |
| أحمد الخالدي  | مؤسس — الباك اند                | **مؤسس مشارك** — **البنية التقنية وقواعد البيانات** |
| زياد النميلات | مؤسس — الباك اند                | **مؤسس مشارك** — **الأمان والبنية التحتية**         |

التغييرين: (1) "مؤسس" → "مؤسس مشارك" (Co-founder) لتوضيح إنه تأسيس جماعي
مشترك مش 3 تأسيسات منفصلة، (2) تمييز مسمّى أحمد عن زياد بدل التكرار الحرفي —
بالاعتماد على وصف كل وحد منهم الموجود أصلاً بالبيانات (`d` بملفات الترجمة).

**الملفات المعدَّلة**: `src/i18n/locales/ar.pages.json`,
`src/i18n/locales/en.pages.json` (مفتاح `about.team`).
