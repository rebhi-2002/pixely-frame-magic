# دليل ربط Sentry — خطوة بخطوة (للمبتدئين)

هذا الدليل مكتوب على افتراض إنك أول مرة تتعامل مع Sentry، حتى لو عندك حساب
مربوط بـGitHub أصلاً. الهدف: تطلع بـ4 قيم فعلية تحطها بمكانين مختلفين
(مو مكان واحد — هاي أكتر نقطة بتلخبط).

---

## أول شي: ليش عندك حساب أصلاً بس المشروع لسا "مش مربوط"؟

ربط حسابك بـGitHub (تسجيل الدخول عبر GitHub) **غير** عن ربط **مشروع Sentry
محدد** (يُسمى "Project" بلغة Sentry) بكودك. حسابك ممكن يكون موجود وفاضي —
بدون أي Project جواه، أو فيه Project لكن بإعدادات مختلفة عن يلي بالكود.
اللي بيهمنا هون 4 قيم محددة، مش مجرد "تسجيل دخول ناجح".

**إذا "بيجي أخطاء"** لما تحاول تربطه — هاي غالباً أحد سببين:

1. لسا ما أنشأت Project فعلي بحسابك (بس عندك الحساب/الـOrganization)، فالقيم يلي بالكود (`voidunemployed`) **قوالب افتراضية مش حسابك**.
2. حطيت القيم بمكان غلط (مثلاً `SENTRY_AUTH_TOKEN` بملف `.env` بدل Vercel Dashboard — وهاد أصلاً السبب الشائع، لأنه بعض القيم لازم تكون بمكان معيّن بالضبط، راجع الجدول تحت).

---

## الخطوة 1 — أنشئ Project (مو Organization، مو حساب جديد)

1. سجّل دخول بحسابك الحالي على [sentry.io](https://sentry.io).
2. من القائمة الجانبية: **Projects** → **Create Project**.
3. Platform: اختار **React** (أقرب خيار متوفر — TanStack Start مو مدرج
   لحاله بقائمة المنصات، بس React SDK هو نفسه المستخدم بالكود
   `@sentry/tanstackstart-react`، فما في مشكلة).
4. اختار اسم للمشروع (مثلاً `academia-frontend`) واضغط **Create Project**.
5. بعد الإنشاء مباشرة، Sentry بيعرضلك صفحة فيها **DSN** — انسخه، هاد أول قيمة.

---

## الخطوة 2 — وين تلاقي كل قيمة بالضبط

| القيمة           | وين تلاقيها                                                                                                                                                          |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **DSN**          | نفس صفحة إنشاء المشروع، أو لاحقًا: **Settings → Projects → (اسم مشروعك) → Client Keys (DSN)**                                                                        |
| **Org slug**     | من رابط أي صفحة بلوحة التحكم نفسها: `sentry.io/organizations/`**`هون-هو-الـslug`**`/...` — أو **Settings → General Settings** بالـOrganization                       |
| **Project slug** | **Settings → Projects → (اسم مشروعك) → General Settings** — حقل "Name" (بالـslug، مو الاسم المعروض)                                                                  |
| **Auth Token**   | **Settings** (أيقونة الترس بأعلى يمين) → **Auth Tokens** → **Create New Token**. الصلاحية المطلوبة بس: `project:releases` (ما تعطيه صلاحيات أكتر من هيك، مش محتاجها) |

---

## الخطوة 3 — 4 قيم، مكانين مختلفين (**الأهم بكل الدليل**)

الفرق بينهم: قيمة **آمنة تنكشف بالمتصفح** (Client-side)، وقيمة **سرّية
لازم تختفي عن أي حد** (وقت البناء بس). كل وحدة إلها مكان مختلف:

### أ) بملف `.env` عندك محلياً (للتطوير على جهازك)

```bash
# آمنة، مش سرّية — هاي بتنكشف أصلاً بالمتصفح لأي زائر (طبيعة الـDSN)
VITE_SENTRY_DSN="https://xxxxxxxx@xxxxx.ingest.sentry.io/xxxxxxx"
```

بس. القيم الثلاث الباقية (`SENTRY_ORG`, `SENTRY_PROJECT`,
`SENTRY_AUTH_TOKEN`) **ما تحطهم بملف `.env` المحلي إطلاقًا** إلا إذا بدك
تجرّب رفع source maps محلياً (نادر، تجاهله الآن).

### ب) بـ Vercel Dashboard (للإنتاج — هون بيصير الربط الحقيقي)

اذهب لمشروعك بـVercel → **Settings** → **Environment Variables**، وضيف
الأربعة:

| الاسم               | القيمة                | Sensitive؟                     |
| ------------------- | --------------------- | ------------------------------ |
| `VITE_SENTRY_DSN`   | الـDSN من الخطوة 1    | لأ                             |
| `SENTRY_ORG`        | الـslug من الجدول فوق | لأ                             |
| `SENTRY_PROJECT`    | الـslug من الجدول فوق | لأ                             |
| `SENTRY_AUTH_TOKEN` | التوكن من الخطوة 2    | **إي — فعّل خيار "Sensitive"** |

⚠️ **`SENTRY_AUTH_TOKEN` سرّي حقيقي** — أي حد يشوفه يقدر يرفع كود وهمي
باسم مشروعك على Sentry. بـVercel، فعّل خيار "Sensitive" جنب القيمة (بيخفيها
حتى عن أعضاء الفريق بعد الحفظ). **لا تحطه أبدًا بملف `.env` مرفوع لـGitHub**
(ملفك `.env` أصلاً مستثنى بـ`.gitignore` عندك — تمام، خليه هيك).

---

## الخطوة 4 — أي كود لازم تعدّل؟ **ولا سطر واحد**

كل الـwiring جاهز بالمشروع من زمان، بيقرأ نفس الأسماء بالضبط يلي حطيتها فوق:

- `src/instrument.client.ts` — تهيئة Sentry بالمتصفح، بتقرأ
  `VITE_SENTRY_DSN`.
- `src/server.ts` — تهيئة Sentry بالسيرفر (SSR)، نفس المتغيّر.
- `vite.config.ts` — بلوجن رفع الـsource maps وقت البناء، بيتفعّل **بس**
  لو `SENTRY_AUTH_TOKEN` موجودة (بدونها، الخطوة هاي تُتجاهل تلقائيًا —
  مافي خطأ).

يعني: ضيف الأربعة بـVercel، اعمل push عادي، وخلص.

---

## الخطوة 5 — تأكد إنه اشتغل فعلاً

1. بعد أول نشر بعد إضافة المتغيرات، افتح موقعك المنشور، وافتح console
   المتصفح — دوّر على أي رسالة من Sentry تأكيد التهيئة (عادة صامتة لو كل
   شي تمام، بس مافيش خطأ اتصال بالـconsole هو المؤشر).
2. جرّب تسبب خطأ متعمّد (مثلاً افتح رابط صفحة مش موجودة أو زر معطّل)،
   وشوف لو ظهر بلوحة Sentry (**Issues** بالقائمة الجانبية) خلال دقيقة أو
   دقيقتين.
3. لو ظهر: مبروك، جاهز — أي خطأ إنتاجي جاي (متل عطل الموقع أو خطأ
   Register يلي صلّحناهم اليوم) هيك بيوصلك تلقائياً بستاك تريس كامل، بدون
   ما تحتاج تنسخلي سجلات Vercel يدوياً كل مرة.

---

## ملخص سريع (لو ضعت بالتفاصيل)

```
1. sentry.io → Create Project (React) → انسخ DSN
2. Settings → Auth Tokens → New Token (صلاحية project:releases)
3. Vercel → Settings → Environment Variables → ضيف الأربعة
   (SENTRY_AUTH_TOKEN = Sensitive)
4. ولا تعديل كود — push عادي وخلص
```
