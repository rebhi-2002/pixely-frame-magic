فحص شامل لكل الـcontrollers الجديدة بالباك اند (`Acadimia-main.zip`) + ملفات
الـSRS، مقابل الفرونت الحالي. الهدف: كتالوج واضح — شو جاهز نربطه فوراً، شو
محتاج بناء فرونت من الصفر، وشو فيه فجوة/تعارض لازم قرار قبل الربط. **الربط
الفعلي لسا ما صار** (متل ما طلبت — هاد بس الخريطة).

## 1) الأمان — صلّحته اليوم بالتوازي مع الفحص

فحصت الـ12 controller (القديمة + الجديدة): **`[Authorize]` كانت موجودة بس
على `AuthController`** — الباقي كلهم بدون حماية فعلية على مستوى الكود. صلّحت:

- `Program.cs`: fallback policy إجبارية (`RequireAuthenticatedUser`) —
  الافتراضي هلق "محمي" بدل "مفتوح".
- تصحيح سلوك كوكي المصادقة: 401 JSON لطلبات `/api/*` بدل 302 redirect
  (كان رح يكسر كل استدعاء API غير مُصادَق لو ما صلّحتها).
- `[AllowAnonymous]` صريحة بس على النقاط يلي **لازم** تكون عامة (تصفّح قبل
  تسجيل الدخول):
  - `UserController.CreateEditModal` (تحتاجها صفحة `/signup` الحالية —
    راجع الملاحظة بالكود، مش تصميم مثالي، الأفضل لاحقًا endpoint عام مخصّص)
  - `TeacherController.Search`, `PublicProfile`, `Availability`
  - `CourseController.GetAll`, `GetById`

**الملفات المعدَّلة** (كلها مرفقة بالأسفل): `Program.cs`,
`UserController.cs`, `UsersService.cs`, `TeacherController.cs`,
`CourseController.cs`, `Services/Courses/CourseService.cs`.

⚠️ **لسا ما فحصت**: `BookingController` و`LessonController` — هل فيهم أي
نقطة لازم تكون عامة؟ من قراءتي للـDTOs، لا أعتقد (الحجز والجدولة أفعال
تحتاج حساب بطبيعتها) — بس لازم تأكيد قبل الربط الفعلي.

### BookingController (كامل — صفر واجهة فرونت حالياً)

### LessonController (كامل — صفر واجهة فرونت حالياً)

فرونت.**

## 3) فجوة منتج مهمة لازم تتحسم قبل الربط: "مسجّل مسبقاً" مش موجودة بالباك اند

راجعت `CourseDeliveryType` enum بالباك اند:

```csharp
public enum CourseDeliveryType { InPerson = 1, Online = 2 }
```

**بس قيمتين.** بينما موديل عملك يلي وصفته (أونلاين مباشر / وجاهي /
**مسجّل مسبقاً**) وموديل بياناتنا بالفرونت (`CourseFormat` بـ
`public-catalog-data.ts`) فيه **3 قيم**. لا `Course` ولا أي DTO بالباك اند
فيه أي حقل لمحتوى مسجّل (فيديو مرفوع، مشاهدة حرة بدون جدولة).

**الخيارات المطروحة** (قرار عملك/منتجك، مش قرار تقني بس):

1. الباك اند يحتاج تعديل: يا إما قيمة enum ثالثة (`Recorded = 3`)، يا إما
   مفهوم منفصل كليًا ("Course" مباشر/وجاهي عبر Booking+Lesson، و"محتوى
   مسجّل" منتج مختلف بالكامل بدون جدولة/معلم-توفّر).
2. لو "مسجّل مسبقاً" مو أولوية حالية، نأجّله ونربط الفرونت بس بـ
   Online/InPerson لهلق، ونخلي حقل الصيغة بالفرونت يدعم الاثنين بس مؤقتًا.

## 4) خطوات مقترحة (بترتيب منطقي، مش إجباري)

1. **قرار سريع**: شو مصير "مسجّل مسبقاً" (قسم 3) — بيأثر على شكل أي ربط جاي.
2. **ربط تصفّح المعلمين/الكورسات العام أول** (أبسط جزء، أقرب لبنية موجودة
   أصلاً بالفرونت — `/courses`, `/teacher/$id`).
3. **بناء واجهة الحجز** (Booking) — أكبر قطعة فرونت جديدة، صفر بداية حالية.
4. **بناء واجهة جدولة الدروس ولوحة المعلم** (Lesson + UpdateProfile +
   SetAvailability + ConfigureGroupSchedule).
5. **حسم مين ينشئ الكورس** (أدمن نيابة عن معلم، ولا المعلم مباشرة) — بيأثر
   على شكل `course-catalog-manager.tsx` الحالي.
