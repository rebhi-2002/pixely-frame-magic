# Academia — UX/UI + Visual Design Audit v1.0

> **مصدر الأدلة:** فحص مباشر لريبو `pixely-frame-magic` (الفرونت) + `Acadimia`
> (الباك اند) + 19 screenshot حقيقي من `academia-platform.vercel.app`
> (عام/مصادقة/أدمن، ثيم فاتح وغامق، عربي بشكل أساسي).
> كل ملاحظة مصنّفة: **[كود]** = دليل من الملفات، **[صورة]** = دليل من
> screenshot فعلي، **[استنتاج]** = رأي تصميمي بدون دليل مباشر (يُذكر صراحة).
> لا تعديل على أي كود ضمن هذا التسليم — audit فقط.

## 1. الخلاصة التنفيذية

Academia عندها **أساس هندسي قوي وغير معتاد بمشاريع بهالحجم**: design
tokens منضبطة، انضباط RTL/LTR ممتاز (12 استثناء فيزيائي فقط بكامل
المشروع وكلها مبرَّرة)، نظام motion موحّد عبر مكوّن واحد (`Reveal`)
بدل قيم حرة متفرقة، وتوثيق داخلي جدي (`docs/design/*.md`) **[كود]**.
هاد مو الوضع المعتاد لمشروع طالب/فردي — عادةً هاي الطبقة هي اللي بتكون
مفقودة، وهون هي موجودة.

المشكلة الحقيقية مو بالهندسة. المشكلة إنه **كل صفحة عامة تقريبًا
مبنية من نفس القالب الثلاثي**: hero بخلفية gradient غامقة + دائرة
زخرفية عائمة ← صف كروت icon+عنوان+وصف بزوايا دائرية ← footer بثلاث
أعمدة. هاد القالب يتكرر بشكل شبه حرفي على 9 من أصل 11 صفحة تسويقية
فحصتها (الرئيسية، كيف تعمل، الأسعار، للمعلمين، من نحن، تواصل معنا،
الكورسات، دليل المعلمين، وغيرها) **[صورة]**. ونفس الشي عند صفحات
المصادقة: تسجيل الدخول وإنشاء حساب يستخدمان **نفس illustration
ونفس نص التسويقي على اليمين حرفيًا** **[صورة]**.

هاد بالضبط تعريف "Design System بدون Design Identity" اللي اتفقنا
عليه بالسياق المرفق — والدليل هلق مو نظري، هو موجود بالصور.

## 3. المشاكل — مرتبة حسب الأثر

### 3.1 تكرار القالب عبر الصفحات (أعلى أولوية) — [صورة]

كل صفحة من: الرئيسية، كيف تعمل، الأسعار، للمعلمين، من نحن، تواصل
معنا، الكورسات، دليل المعلمين تبدأ بنفس البنية:

```
[navbar غامق ثابت]
[hero: خلفية gradient بزاوية + دائرة/نقطة زخرفية عائمة + عنوان + وصف]
[صف كروت: زاوية دائرية كبيرة + دائرة icon + عنوان + سطرين وصف]
[footer 3 أعمدة]
```

هاي بالضبط لائحة "AI anti-patterns" اللي بالسياق المرفق: generic
gradient hero، decorative blobs، identical page structures، icon+title+
description pattern، excessive rounded containers. المشكلة مو إنها
"قبيحة" — هي **متقنة تقنيًا** بس **predictable**، وهيك بتفقد أي صفحة
هويتها الخاصة (فرق "كيف تعمل" عن "الأسعار" عن "من نحن" صفر تقريبًا
غير النص).

**دليل إضافي [صورة]:** صفحتَي تسجيل الدخول وإنشاء الحساب تستخدمان
حرفيًا نفس illustration (متصفح صغير برسم بياني + 3 نقاط ملونة) ونفس
عنوان "كل أدوات التنظيم والتحضير بمكان واحد" ونفس القائمة الثلاثية
تحته. مستخدم بيتنقل بين الصفحتين ما بيحس بفرق.

### 3.2 صفحة "من نحن" تستخدم أيقونات بدل صور حقيقية للفريق — [صورة]

قسم "الفريق" يعرض 3 أعضاء مؤسسين بدوائر تحمل **أيقونات عامة**
(قلب/بوصلة/أيقونة كود) بدل صور شخصية حقيقية. هاي أكتر صفحة بالموقع
المفروض تبني ثقة بشرية (Trust) — وهي بالضبط المكان اللي السياق
المرفق حذّر منه: استبدال الصورة الحقيقية بـ icon داخل دائرة ملوّنة.
هاد أوضح فجوة بين "عندنا استراتيجية صور" و"التنفيذ الفعلي".

### 3.3 لوحة الأدمن: نمط SaaS dashboard عام — [صورة]

4 كروت متطابقة (icon دائرة + رقم كبير + تسمية) بصف أفقي، بانر ترحيب
بخلفية gradient بزاوية مع illustration صغيرة، ثم bar chart بسيط تحته.
هاد نمط "admin panel template" قياسي — وظيفيًا صحيح 100%، لكن بصريًا
غير مميّز ولا يعكس إنه منتج تعليمي متخصص. القيم كلها صفر بالسكرين شوت
(بيئة تجريبية)، فما قدرنا نحكم على كثافة المعلومات بحالة استخدام حقيقي
— هاي نقطة تحتاج مراجعة مع بيانات حقيقية قبل إعادة تصميم نهائية.

### 3.4 غياب Photography كليًا — [صورة] + [كود]

ولا صورة فوتوغرافية واحدة ظهرت بأي من الـ19 screenshot. كل التواصل
البصري يعتمد على: أيقونات (Lucide على الأغلب حسب أسلوب الكود)، أشكال
هندسية، ودوائر gradient. هاد يتماشى مع ملاحظة السياق المرفق حرفيًا.
ما لقيت أي مجلد `public/images` أو نظام أصول صور بالريبو وقت الفحص
— يعني هاي فجوة بنيوية مو بس قرار تصميمي مؤجّل: **[استنتاج]** المشروع
لسا ما بنى pipeline لاستيراد/تحسين/عرض صور حقيقية (aspect ratio,
lazy loading, srcset)، وهاد لازم يُبنى قبل ما نقدر "نحط صور" فعليًا.

### 3.5 Hero pattern الموحّد يُضعف الصفحة الرئيسية تحديدًا — [صورة]

بالنسخة الفاتحة/الإنجليزية المرفقة، الـhero فيه فعلاً عنصر مختلف
(mockup لوحة تحكم داخل نافذة متصفح، مع badge "12 lessons done this
week")، وهذا أفضل بكتير من نسخة "كيف تعمل"/"الأسعار" اللي هي نص +
خلفية فاضية. المشكلة: هاد الـmockup **موجود بس مرة وحدة** (الصفحة
الرئيسية)، وباقي الصفحات رجعت لنفس القالب الفاضي. هاد دليل إنه الفريق
عنده *قدرة* يبني عنصر بصري مميّز (الـdashboard mockup شغل جيد فعلاً)،
بس ما طُبّق بشكل منهجي على بقية الصفحات.

### 3.6 عدم اتساق الثيم/اللغة وقت الالتقاط — [صورة]

- صفحة "من نحن" ظهرت بالثيم الفاتح بينما باقي الصفحات بالثيم الغامق.
- الصورة الإنجليزية المرفقة (light theme) تُظهر hero أقوى بصريًا من
  النسخة العربية الغامقة لنفس الصفحة تقريبًا (اختلاف بالـcopy مو بس
  اللغة — "Organize your Tawjihi study" مقابل "رتّب دراسة التوجيهي").
  هاد على الأغلب فرق بمحتوى تسويقي بين نسختين قيد التطوير، مو خلل —
  بس **[استنتاج]** يستاهل التأكد إنه القرار (أي نسخة copy هي
  النهائية) واعي ومو نتيجة صدفة تعديلين متوازيين.
- هاد مو مشكلة تصميم بحد ذاته، بس بيأثر عالقدرة نقيّم اتساق كل صفحة
  بكل حالاتها (فاتح/غامق × عربي/إنجليزي) بدقة كاملة بهالجولة.

### 3.7 كثافة الكروت المتطابقة داخل الصفحة الواحدة — [صورة]

صفحة "للمعلمين" مثلاً: 4 كروت أفقية متتالية بنفس الشكل تمامًا (icon
دائرة يمين + عنوان + وصف) لعرض 4 أفكار مختلفة تمامًا بالأهمية
(محتوى محفوظ، تحليلات، دخل، حساب موثّق). كلهم يحصلون نفس الوزن
البصري رغم إنه منطقيًا "الدخل من المحتوى" و"حساب موثّق" أهم لمعلم
جديد مقارنة بالتفاصيل التقنية. هاد مثال مباشر لمبدأ "كل CTA/قسم يُعطى
نفس التأكيد البصري" من لائحة الـanti-patterns.

## 4. Information Architecture والتنقل — [صورة] + [استنتاج محدود]

- القائمة العلوية بالموقع العام ثابتة ومتسقة عبر كل الصفحات (نفس
  الترتيب: الرئيسية، الكورسات، دليل المعلمين، كيف تعمل، الأسعار،
  للمعلمين، لأولياء الأمور) — هاد جيد، IA واضحة ومتوقعة.
- بالأدمن، القائمة الجانبية تفصل بوضوح: مساحة الطالب/المعلم/الإشراف
  الأكاديمي/ولي الأمر/الإدارة/الشؤون الأكاديمية — بنية منطقية جيدة
  ومتوافقة مع الأدوار الموثقة بالـSwagger (Student/Teacher/Parent/
  Admin controllers).
- **ملاحظة [استنتاج]:** ما قدرت أفحص user journeys الفعلية جوا لوحات
  الطالب/المعلم/ولي الأمر لأنه الصور المرفقة تغطي بس الصفحات العامة
  + لوحة أدمن واحدة. أي حكم على تلك اللوحات بهالمرحلة استنتاج مو دليل
  مباشر — لازم screenshots إضافية أو وصول فعلي قبل audit نهائي لهاي
  الأقسام تحديدًا.

## 5. Typography — [كود]

المقياس موجود ومنضبط (`text-xs`→`text-5xl` + `text-nav`/`text-micro`
موثّقين)، و4 عائلات خط معرّفة بدور واضح لكل وحدة:

| الدور | الخط | الاستخدام |
|---|---|---|
| Display عربي | Tajawal / Cairo (fallback) | عناوين كبيرة عربية |
| Display إنجليزي | Reem Kufi | عناوين كبيرة إنجليزية |
| Body | Cairo | محتوى عام |
| تقني/أرقام | IBM Plex Mono | محتوى تقني |

هاد نظام مدروس فعلاً ومو قرار عشوائي — **لا يحتاج استبدال**. اللي
ناقص مو الخط نفسه، هو **الاستخدام التبايني**: بالصور، العناوين
بمعظم الصفحات الداخلية (كيف تعمل، الأسعار) تستخدم وزن/حجم قريب جدًا
من بعض بدل تدرّج هرمي واضح (display قوي جدًا مقابل body). هاد قرار
تركيب composition مش قرار خط.

## 6. Color — [كود]

نظام ألوان دلالي كامل (`primary`, `secondary`, `success`, `info`,
`destructive`, `chart-1..5`, `sidebar-*`...) مبني على tokens غامقة
أساسية (`--ink-950: #0a0f1c`) مع لون primary ذهبي/عنبري دافئ (واضح
بالصور: أزرار "ابدأ مجانًا" والتمييزات). هاد **فعلاً يبتعد عن** كليشيه
"dark blue SaaS glow" المذكور بالسياق المرفق — اللون الدافئ (ذهبي)
كخيار primary بدل الأزرق/البنفسجي هو أحد أقوى عناصر الهوية الموجودة
فعلاً بالمشروع، وياريت يُبنى عليه أكتر مو يُستبدل.

المشكلة اللي بالصور مو الألوان نفسها، هي إنه **التطبيق يتكرر بنفس
النمط**: gradient بزاوية (من غامق لـ عنبري شفاف) كخلفية hero بكل
صفحة تقريبًا. اللون صح، التوزيع (composition) متكرر.

## 7. Layout / Composition — [صورة]

- **لا يوجد تمايز بين page archetypes.** الصفحة التسويقية، صفحة
  المصادقة، صفحة اكتشاف المعلمين، ولوحة الأدمن كلهم يشتركون بنفس
  منطق "hero علوي + كروت بزوايا دائرية بالأسفل" ولو بنسب مختلفة.
- الـgrid المستخدم بمعظم الأماكن symmetric (كروت متساوية الحجم بصف).
  ولا شفت مثال composition غير متماثل (عمود كبير + عمود صغير، صورة
  full-bleed، نص يمتد فوق صورة...) بأي من الصور.
- جدول مقارنة الأسعار هو أفضل مثال composition موجود فعليًا (كثافة
  معلومات عالية، هرمية واضحة بين خطة premium/مجانية) — نموذج جيد
  يستاهل يتوسع كنمط لصفحات ثانية معقدة المعلومات (مثلاً Wallet،
  Exam results).

## 8. Error / Loading / Empty States — [صورة]

نقطة إيجابية غير متوقعة: صفحتَي "الكورسات" و"دليل المعلمين" أظهرتا
حالة خطأ API حقيقية (فشل اتصال بالسيرفر) بتصميم متسق: أيقونة تحذير
حمراء بدائرة + عنوان + وصف + زر "إعادة المحاولة". هاد **نمط جيد
ومتكرر بشكل مقصود** (نفس البنية بالصفحتين) — عكس باقي التكرار المذكور
بقسم 3، هاد النوع من التكرار **مطلوب ومرغوب** (اتساق أنماط الأخطاء
عبر النظام). لا تغيّر هاد النمط، فقط أعد تصميمه بصريًا بما يماشي
الهوية الجديدة إذا لزم.

## 9. AI Design Anti-Patterns — ملخص الأدلة المباشرة

| النمط | موجود؟ | أين (دليل) |
|---|---|---|
| Identical page structures | ✅ | 9 صفحات عامة [صورة] |
| Icon + title + description cards | ✅ | كل صفحة تسويقية تقريبًا [صورة] |
| Generic gradient hero | ✅ | كل الصفحات الداخلية [صورة] |
| Decorative blobs/dots | ✅ | hero بمعظم الصفحات + auth screens [صورة] |
| Excessive rounded containers | ✅ | كروت الأسعار/كيف تعمل/للمعلمين [صورة] |
| Icon بدل صورة حقيقية للأشخاص | ✅ | صفحة "من نحن" — الفريق [صورة] |
| Generic split-screen auth | ✅ | تسجيل الدخول/إنشاء حساب [صورة] |
| Generic admin dashboard stats grid | ✅ | لوحة الأدمن [صورة] |
| Animation بلا غرض | ❌ غير موجود | نظام `Reveal` مقصود وموثّق [كود] |
| Blue-glow dark SaaS aesthetic | ❌ غير موجود | primary ذهبي/عنبري دافئ فعليًا [كود]+[صورة] |
| Glassmorphism مفرط | ⚠️ غير واضح من الصور | يحتاج فحص CSS مباشر لاحقًا |

النقطتين الأخيرتين مهمتين: Academia **مو غارقة بكل** الـanti-patterns
المذكورة بالقائمة الطويلة بالسياق المرفق — بالعكس، خيار اللون
ونظام الـmotion فعليًا يبتعدان عنها. المشكلة مركّزة وواضحة: **تكرار
البنية (composition) عبر الصفحات + غياب الصور الحقيقية**، مو "كل شي
غلط".

## 10. Academia Design Direction v1.0 (مقترح أولي)

> هاد **مقترح للنقاش**، مو قرار نهائي — الهدف يكون نقطة بداية
> لمحادثة، مو implementation spec.

**الهوية المرئية الحالية (المبنية فعليًا بالكود) عندها أساس صح:**
لون عنبري/ذهبي دافئ على خلفية غامقة عميقة (`#0a0f1c`)، بدل الأزرق/
البنفسجي الشائع بـSaaS العربي — هاد فرق حقيقي، ابنِ عليه بدل تغييره.

**المطلوب فوق هاد الأساس:**

1. **Page archetypes حقيقية** — الصفحة الرئيسية تختلف تركيبًا عن
   "الأسعار" تختلف عن "من نحن" تختلف عن "دليل المعلمين". أقل تدخل:
   ابدأ بصفحتين بس (الرئيسية + من نحن) كنموذج تجريبي قبل تعميم أي
   نمط جديد.
2. **صور حقيقية بأماكن الثقة تحديدًا أولًا**: صفحة "من نحن" (صور
   المؤسسين الفعلية)، وبروفايل المعلم العام (`Teacher/PublicProfile`
   بالـSwagger) — هاد أعلى أثر لأقل جهد، مو استبدال كل icon بكل مكان.
3. **توسيع نمط الـdashboard mockup** (الموجود فعلاً بالـhero الرئيسي)
   ليكون العنصر البصري المميّز لصفحات ثانية بدل تكرار gradient+دائرة.
4. **تفعيل composition غير متماثل بحد أدنى**: عمود نص + عمود صورة/
   mockup بدل كروت متساوية بصف، على الأقل بصفحات "للمعلمين"/"لأولياء
   الأمور" اللي فيها قصة (narrative) مو بس ميزات.

## 11. توصيات مرتّبة (بدون كود بعد)

### أولوية عالية — أثر كبير / جهد معقول
1. استبدال أيقونات فريق "من نحن" بصور حقيقية (أو illustration بشري
   مقصود إذا صور فعلية غير متاحة الآن) — أعلى صفحة ثقة وأسهل نطاق.
2. تصميم hero مختلف لصفحتي تسجيل الدخول وإنشاء حساب (على الأقل illustration
   مختلف بينهم) — أكتر تكرار حرفي لاحظناه.
3. بناء نسخة composition ثانية (غير الكروت الأفقية المتطابقة) لصفحة
   واحدة تجريبية (اقتراح: "للمعلمين" لأنها الأغنى قصةً) كـproof of
   concept قبل تعميم أي تغيير.

### أولوية متوسطة
4. توسيع استخدام نمط "dashboard mockup" (من الـhero الرئيسي) كعنصر
   بصري متكرر بنسخ مختلفة بدل gradient+دائرة الفارغة.
5. مراجعة لوحة الأدمن بصريًا **بعد** توفر بيانات حقيقية (الأرقام
   حاليًا صفر بكل الكروت، صعب الحكم على كثافة المعلومات الفعلية).

### أولوية منخفضة / يحتاج معلومات إضافية أولًا
6. بناء Photography direction كاملة (نوع الصور، معالجة، aspect
   ratios) — يحتاج قرار مسبق: هل في ميزانية/مصدر صور حقيقية أصلًا؟
   بدون هاد الجواب أي "استراتيجية تصوير" نظرية فقط.
7. مراجعة لوحات الطالب/المعلم/ولي الأمر الداخلية — **لا يوجد دليل
   مصور كافٍ بهالجولة**، يحتاج screenshots إضافية قبل أي حكم.

## 12. ما لا يجب تغييره إطلاقًا

- نظام الـdesign tokens الدلالي بـ`src/styles.css` — البنية سليمة.
- مكوّن `Reveal` ونظام الـvariants — حل صحيح لمشكلة حقيقية، أي بديل
  جديد (مكتبة animation، قيم حرة بالصفحة) خطوة للخلف.
- انضباط RTL/LTR الحالي (logical properties) — خطر كبير لو "تحسين
  بصري" كسره بدون اختبار على الاتجاهين.
- Typography scale ومقياس الخطوط الأربعة — الأساس صحيح، المطلوب
  استخدام تبايني أقوى مو استبدال.
- خيار اللون العنبري/الذهبي كـprimary — فرق حقيقي عن الكليشيه، ابنِ
  عليه.
- بنية error/loading/empty states الحالية — نمط متسق ومقصود، أعد
  تصميمه بصريًا فقط إذا لزم، لا تعيد بناء منطقه.
