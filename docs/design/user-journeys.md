# Academia — User Journeys

المصدر: الأقسام 14–17 من `ACADEMIA-DESIGN-CONTEXT.md` + `docs/architecture/system-design-and-gap-analysis.md`.
القاعدة: الرحلة هي **العمود الفقري للـUX**؛ لا نبدأ من "كيف نجمّل اللوحة".

## 1) الطالب `[SRS]`

```
اكتشاف معلم/كورس → تقييم → حجز/انضمام → دفع/محفظة →
موافقة → جدولة → درس → حضور → اختبار → تقدّم → الخطوة التالية
```

انعكاس على الواجهة:

| المرحلة | الصفحة | المطلوب بصريًا |
|---|---|---|
| اكتشاف | `/teachers`, `/courses` | صورة المعلم كمعلومة + إشارات ثقة |
| تقييم | `/teacher/$id` | هوية → ثقة → خبرة → توفّر → حجز |
| جدولة | `/schedule` | زمن مقروء لا جدول بيانات |
| درس | `/library/lesson/$id` | محتوى → تقدّم → الفعل التالي |
| اختبار | `/exam-simulator` | تركيز، بلا زخرفة ولا حركة |
| تقدّم | `/dashboard`, `/achievements` | اتجاه ومقارنة لا أرقام مجرّدة |

**قاعدة**: لوحة الطالب يجب أن تجيب سؤالًا واحدًا فوق الطية: *ما خطوتي التالية الآن؟*

## 2) المعلم `[SRS]`

```
إنشاء الملف → قابلية الاكتشاف → استلام حجز → قبول/رفض →
جدولة → تدريس → حضور → تقييم → أرباح → سحب
```

الملف العام للمعلم (مؤهلات، خبرة، نطاق الخدمة، اللغات، حضوري/أونلاين، سعر الساعة، صورة) هو **أكبر فرصة تميّز بصري في المنتج** (القسم 15) — يُعامل كصفحة marketplace لا كصفحة إدارية.

## 3) ولي الأمر `[SRS: read-only monitoring]`

```
أبنائي → اختيار الابن → الحالة الأكاديمية → الحضور →
الاختبارات → التغيّرات الأخيرة → الإشعارات
```

**قاعدة**: اختيار الابن يسبق أي بيانات. النبرة "مراقبة واطمئنان"، لا "مساحة عمل".

## 4) الأدمن

```
طوابير القرار → توثيق المعلمين → مراجعة المحتوى → البلاغات →
المنهاج والطلبات → المدفوعات → المستخدمون والأدوار → تدقيق
```

الأولوية: الكثافة التشغيلية. جداول، فلاتر، حالات، طوابير، لا hero ولا رسوم كبيرة.

## 5) المشرف الأكاديمي

نفس نمط الأدمن لكن **بنطاق أضيق**: معلمون ضمن نطاقه، متابعة طلاب، تقارير. التمييز بالنطاق والعنونة، لا بجمالية مختلفة.

## خريطة "الفعل التالي" لكل دور

| الدور | الفعل الأساسي الذي يجب أن يكون الأبرز في الشاشة |
|---|---|
| طالب | متابعة الدرس / أداء الاختبار المستحق |
| معلم | الرد على حجز جديد |
| ولي أمر | فتح تقرير الابن الأحدث |
| أدمن | أقدم عنصر في طابور القرار |
| مشرف | حالة تحتاج تدخّلًا داخل نطاقه |
